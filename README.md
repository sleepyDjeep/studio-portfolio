# Studio Portfolio — Partner & Collaborator Guide

Plain-English interactive atlas of every software platform, game engine, AI workflow, executive business plan, creative pipeline, and hardware build created in our studio since **August 16, 2026** (when our Unified Memory Bank went live).

---

## Quick Start (Live Web &amp; Zero-Setup Offline)

- **Live Web Atlas**: `https://sleepydjeep.github.io/studio-portfolio/` (plus the standalone 45-render [15-World Concept Atlas](https://sleepydjeep.github.io/studio-portfolio/atlas.html)).
- **Offline Local Bundle**: Open [index.html](file:///D:/Projects/Studio_Portfolio/index.html) directly in any desktop or mobile browser (`file:///D:/Projects/Studio_Portfolio/index.html`).

- **No backend server required**: `portfolio-data.js` bundles all 48 public Markdown guides and inline SVG architecture diagrams into a single static payload.
- **Four ways to browse**:
  1. **Domain Pillars**: Organized across our 5 core studio pillars, starting with *How Our AI Studio Works*.
  2. **By Readiness Stage**: Separates *Shipped / Verified* software from *Reusable Workflows*, *Active Prototypes*, and *Master Blueprints*.
  3. **By Type**: Groups entries into *Projects*, *Workflows*, and *Ideas &amp; Plans*.
  4. **Timeline**: Chronological walk from August 2026 through November 2026 showing how early tools compounded into faster builds.
- **Editorial Light &amp; Dark Studio Modes**: Click the top-right theme button anytime to switch between clean paper-white Editorial Light mode and low-glare Dark Studio mode.
- **Two-Layer Reading**: Every entry opens with plain-English explanations, a concrete `Input -> What Happens -> Output` example, visual proof (`Authentic Capture` vs. badged `Concept Preview`), and honest status—followed by an expandable **Under the Hood &amp; Local Files** drawer for engineering details and launch commands.

## Keeping the Living Portfolio Up to Date

### 1. Check for New Studio Work
Run the incremental detector anytime after new coding or planning sessions:

```powershell
python "D:\Projects\Studio_Portfolio\tools\audit_new_work.py"
```

It compares live LanceDB (`memories.lance`), Antigravity's `conversation_summaries.db`, and `D:\Projects\` against `data/master_manifest.json` and lists every unmapped memory, conversation, or folder.

### 2. Add or Edit an Entry
1. Create or edit a Markdown file inside the matching `docs/<pillar>/` folder using the standard frontmatter and four `##` sections (`What It Is & Why It Matters`, `Real Example: How It Works in Practice`, `Where It Stands & Next Steps`, `Under the Hood & Local Files`).
2. Drop screenshots or audio into `assets/media/<slug>/` (or `assets/concepts/<slug>.png` with `kind: "concept"` for unbuilt blueprints).
3. Rebuild, run all 5 verification gates, and prove the payload is current, with one command:

```powershell
python "D:\Projects\Studio_Portfolio\tools\update_portfolio.py"
```

It runs `build_portfolio.py`, then `verify_portfolio.py`, then `check_bundle_freshness.py`, and stops at the first failure so a broken gate never scrolls past. `--no-verify` skips the gate step on a machine without the local LanceDB and conversation databases.

The freshness step recompiles into a temporary directory and compares that against your `portfolio-data.js`: every entry field, every media item plus the sha256 of the file behind it, the pillar list, the summary counts, and the inception date. It ignores only the `compiled_at` timestamp and the ids that come from the gitignored `data/master_manifest.json`, and it names each drifted entry and field when it fails.

Adding, renaming, or retiring an entry is an explicit act: `tools/expected_entries.json` lists every id that must ship, and the verifier fails both when a listed id has no doc behind it and when a doc appears that the list does not know about. Refresh it with `python tools/verify_portfolio.py --update-baseline`, which refuses to write while any doc fails to parse, and commit the result with the change that caused it. The builder is just as strict: an unreadable fence, a missing `id`, or a duplicate `id` stops it with the file named and nothing written, so a damaged doc cannot be compiled out of the atlas by accident.

### 3. Publish the Rebuilt Bundle

Enable the commit guard once per clone, so a commit cannot ship a payload older than the docs behind it:

```powershell
git config core.hooksPath .githooks
```

The hook runs the freshness check on `git commit` and refuses the commit when the bundle is stale or was left unstaged. Two workflows back it up: `.github/workflows/portfolio-bundle-freshness.yml` rebuilds the payload and re-runs gates 2-5 (`python tools/verify_portfolio.py --skip-coverage`) on every push and pull request to `main`, and `.github/workflows/portfolio-live-freshness.yml` fetches the deployed `portfolio-data.js` once a day and compares it with a clean rebuild, so a Pages deploy that never landed becomes a failed run instead of a quietly stale atlas. The push workflow then runs `python tools/gate_self_test.py`, which breaks one thing at a time on a throwaway copy — a dropped section, a byte appended to an image, an edited doc that was never recompiled — and fails if the matching gate stays green.

CI has no `data/` directory (Gate 5 requires it to stay gitignored), so both workflows build from the committed `tools/public_manifest.json`, which carries the pillar list, the inception date, and the reconciliation counts. Regenerate it from `data/master_manifest.json` whenever those change.
